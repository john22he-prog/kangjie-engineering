# 看板数据分析与联动设计方案（v1.0）

**项目**：康洁工程部小程序（设备配件更换记录与报警）  
**版本**：v1.0（一期 MVP）  
**日期**：2026-02-11  
**适用端**：小程序看板 + PC 管理后台看板  
**数据来源**：云函数 `adminDashboard`（统一聚合）

---

## 1. 看板模块总览（6 个核心模块）

| 模块编号 | 模块名称 | 一期优先级 | 展示形式 |
|----------|----------|-----------|----------|
| M1 | 本月更换总览（数字卡） | **必做** | 数字卡片 |
| M2 | 配件消耗 TOP 5 | **必做** | 柱状排名 / 列表 |
| M3 | 设备更换 TOP 5 | **必做** | 柱状排名 / 列表 |
| M4 | 工程人员工作量 | **必做** | 表格 / 柱状 |
| M5 | 最近 7 天趋势 | 可选 | 折线图 |
| M6 | 报警设备分布 + 下钻明细 | **必做** | 按设备分组列表 → 下钻每条报警+消耗明细+ACK |

---

## 2. 各模块数据分析详情

### 2.1 M1：本月更换总览（核心数字卡）

| 指标 | 数据来源 | 聚合方式 | 分析意义 |
|------|----------|----------|----------|
| 本月更换次数 | `replacement_logs` | 按 `yearMonth` 聚合 count | 反映整体工作量 |
| 本月配件消耗总量 | `replacement_logs.items[].qty` | 求和 | 反映物料消耗规模 |
| OPEN 报警数 | `alerts` where `status=OPEN` | count | **最重要的预警指标**，红色高亮 |
| 环比（可选） | 本月 vs 上月同期 | (本月-上月)/上月 | 发现消耗异常趋势 |

**云函数返回字段**：
```json
{
  "totalLogs": 128,
  "totalParts": 456,
  "openAlerts": 5
}
```

### 2.2 M2：配件消耗 TOP 5 + 下钻明细

#### 2.2.1 看板卡片（TOP 排名）

| 维度 | 数据来源 | 聚合方式 | 分析意义 |
|------|----------|----------|----------|
| 按配件 SKU 的消耗数量降序 | `monthly_part_usage` 本月 | 按 `partSkuId` group → `qtySum` 跨设备求和 → 降序取 TOP 5 | 找出消耗最多的配件，辅助采购决策 |
| 展示字段 | partName + partCode + totalQty | 联查 `parts` 集合 | 一目了然 |

**看板卡片云函数返回**：
```json
{
  "topPartsByQty": [
    { "partSkuId": "SKU-001", "partName": "轴承", "partCode": "BRG-6205", "totalQty": 45 },
    { "partSkuId": "SKU-002", "partName": "密封圈", "partCode": "SEAL-301", "totalQty": 32 }
  ]
}
```

**每行展示字段**：

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| 排名序号 | 按 qtySum 降序 | 直观 |
| 设备名称 + 编号 | `assets` 联查 | 识别设备 |
| 车间/区域 | `assets.workshop` | 定位位置 |
| 该设备本月消耗数量 | `monthly_part_usage` where assetId+partSkuId+yearMonth | 核心数据 |
| 占比 | qty / totalQty × 100% | 看集中度 |
| 阈值 | `asset_part_thresholds` where assetId+partSkuId | 是否接近/超标 |
| 超阈值标记 | qtySum > threshold → 红色⚠ | 预警 |
| 进度条/柱状 | 按数量比例绘制 | 视觉对比 |

**二次下钻（点击某台设备行）**：

```
点击「1号注塑机 - 轴承 18个」
  → 展开/跳转：该设备+该配件的每次更换记录明细
  → 展示：日期 | 数量 | 更换类型 | 部位 | 填报人
  → 按时间倒序
```

**明细展示方式建议**：
- **小程序**：点击后展开折叠面板（accordion），或跳转子页面
- **PC 端**：点击后右侧抽屉（drawer）展开明细表格

**二次下钻明细字段**：

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| 更换日期 | `replacement_logs.ts` | 格式 MM-DD HH:mm |
| 数量 | `replacement_logs.items[]` where partSkuId 匹配 → qty | 该次更换中此配件用了几个 |
| 更换类型 | `replacement_logs.type` | 维修/预防/紧急 |
| 部位 | `replacement_logs.locationNameSnapshot` | 用在哪个部位 |
| 填报人 | `replacement_logs.reporterNameSnapshot` | 谁换的 |
| 备注 | `replacement_logs.remark` | 可选展示 |

### 2.4 M4：工程人员工作量

| 维度 | 数据来源 | 聚合方式 | 分析意义 |
|------|----------|----------|----------|
| 按填报人分组的提交条数 | `replacement_logs` 本月 | 按 `reporterUserIdSnapshot` group count | 衡量每个工程师的工作强度/产出 |
| 展示字段 | displayName + logCount | 联查 `users` 集合 | — |

**权限注意**：普通 Engineer 在小程序端可隐藏此模块，仅 Supervisor/Admin 可见。

**云函数返回字段**：
```json
{
  "engineerWorkload": [
    { "displayName": "张三", "logCount": 15 },
    { "displayName": "李四", "logCount": 12 }
  ]
}
```

### 2.6 M6：报警设备分布 + 下钻明细

#### 2.6.1 看板卡片：按设备的报警分布

> 不只是一个简单列表，而是**按设备分组统计报警数**，让主管一眼看出哪台设备问题最集中。

| 维度 | 数据来源 | 聚合方式 | 分析意义 |
|------|----------|----------|----------|
| 按设备的 OPEN 报警数，降序 | `alerts` where `status=OPEN` 按 `assetId` group count | 分组聚合 | 哪台设备报警最多——需优先排查 |
| 展示字段 | 设备名称/编号 + OPEN报警数 | 联查 `assets` | 一目了然 |

**每条报警展示字段**：

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| 配件名称/编号 | `alerts` 联查 `parts` | 哪个配件超了 |
| 月度阈值 | `alerts.thresholdValue` | 设定值 |
| 当前累计 | `alerts.currentQty` | 实际用量 |
| 超出数量 | currentQty - thresholdValue | 差值，红色 |
| 超阈值比例 | currentQty / thresholdValue × 100% | 进度条展示 |
| 报警时间 | `alerts.createdAt` | 格式 MM-DD HH:mm |
| 状态 | `alerts.status` | OPEN 红色 / ACK 灰色 |
| 消耗明细 | `replacement_logs` where assetId+partSkuId+yearMonth | 该设备+该配件本月的每次更换记录 |
| ACK 按钮 | — | 仅 Supervisor/Admin 可见，点击弹出确认说明输入 |


## 3. 模块联动关系设计

> 联动的核心目的：让主管从"总览 → 发现异常 → 点进详情 → 处理问题"形成完整管理闭环。

### 3.1 全局联动：月份选择器

```
看板顶部有月份选择器（默认本月）
  → 切换月份时，所有 6 个模块同步刷新数据
  → 云函数入参：{ yearMonth: "YYYY-MM" }
```

**意义**：支持回顾历史月份的整体情况，而不仅限于当月。

---

### 3.2 联动 1：OPEN 报警数 → 报警列表页

```
触发：点击 M1 中的「OPEN 报警数」卡片，或点击 M6 中的报警列表项
目标：
  - 小程序：navigateTo('/pages/alerts/index') → 默认 status=OPEN, yearMonth=本月
  - PC 端：router.push('/alert') → 默认 Tab=OPEN, yearMonth=本月
```

**意义**：主管看到报警数字后，直接点进去处理（ACK），形成闭环。  
**优先级**：**必做**（最核心的联动）

---

### 3.3 联动 2：配件消耗 TOP → 配件消耗明细下钻页（核心联动）

```
触发：点击 M2 中某个配件 TOP 项（如"轴承 BRG-6205 — 45个"）
目标：
  - 小程序：navigateTo('/pages/dashboard/part-detail?partSkuId=SKU-001&yearMonth=2026-02')
  - PC 端：router.push('/dashboard/part/SKU-001?yearMonth=2026-02')

下钻第一层：配件→设备分布
  - 展示：哪些设备使用了这个配件，按数量从高到低排列
  - 每行：设备名称/编号 + 车间 + 消耗数量 + 占比 + 阈值状态 + 进度条

下钻第二层：设备+配件→更换记录明细
  - 点击某台设备行 → 展开/跳转该设备+该配件的每次更换记录
  - 每条：日期 | 数量 | 更换类型(维修/预防/紧急) | 部位 | 填报人 | 备注
  - 按时间倒序排列
```

**用户操作路径示例**：
```
看板 "轴承 45个 排名第1"

      02-02 维修 主轴承座 张三 4个 "例行更换"
```

**意义**：主管不仅看到"轴承消耗最多"，还能追溯到**哪台设备消耗最多** → **每次是谁换的、什么情况下换的**，完成从宏观到微观的完整分析闭环。  
**优先级**：**必做**（一期核心联动）

## 5. 一期实现优先级建议

### 5.1 必做（一期上线）

| 模块 | 联动 | 开发成本 | 说明 |
|------|------|----------|------|
| M1 数字卡（更换次数 + OPEN 报警数） | OPEN 报警数 → 报警列表页 | 低 | 主管最关心 |
| **M2 配件消耗 TOP 5** | **点击 → 配件消耗明细下钻页（设备分布+记录明细）** | **中** | **核心联动：从配件→设备→每次明细** |
| **M3 设备更换 TOP 5** | **点击 → 设备消耗明细下钻页（配件分布+记录明细）** | **中** | **核心联动：从设备→配件→每次明细** |
| M4 工程人员工作量 | 静态展示即可 | 低 | 管理需要 |
| **M6 报警设备分布** | **点击某设备 → 设备报警明细下钻页（每条报警+消耗明细+ACK）** | **中** | **核心联动：从设备→该设备全部报警→明细→ACK** |
| 月份全局切换 | 所有模块联动刷新 | 低 | 体验提升大 |

> M2/M3/M6 下钻页需要新增 3 个页面 + 云函数新增 3 个 action（`partDetail` / `assetDetail` / `assetAlerts`），明细记录展示组件可复用。

### 5.2 建议做（一期有余力时）

| 模块 | 联动 | 说明 |
|------|------|------|

## 7. 联动实现要点（技术备注）

### 7.1 小程序端跳转传参

```javascript
// 联动1：从看板跳转到报警列表（默认 OPEN）
wx.navigateTo({
  url: '/pages/alerts/index?status=OPEN&yearMonth=2026-02'
})

// 联动2：从配件消耗 TOP 跳转到配件消耗明细下钻页
wx.navigateTo({
  url: '/pages/dashboard/part-detail?partSkuId=SKU-001&yearMonth=2026-02'
})

// 联动3：从设备更换 TOP 跳转到设备消耗明细下钻页
wx.navigateTo({
  url: '/pages/dashboard/asset-detail?assetId=ZB-001&yearMonth=2026-02'
})

// 联动4：从工程人员工作量跳转到记录列表（按人员筛选）
wx.navigateTo({
  url: '/pages/record/index?yearMonth=2026-02&userId=U-001'
})

// 联动6：从报警设备分布跳转到设备报警明细下钻页
wx.navigateTo({
  url: '/pages/dashboard/asset-alerts?assetId=ZB-001&yearMonth=2026-02'
})
```

### 7.2 PC 端路由跳转传参

```javascript
// 联动1：从看板跳转到报警管理
router.push({ path: '/alert', query: { status: 'OPEN', yearMonth: '2026-02' } })

// 联动2：从配件消耗 TOP 跳转到配件消耗明细下钻页
router.push({ path: '/dashboard/part/SKU-001', query: { yearMonth: '2026-02' } })

// 联动3：从设备更换 TOP 跳转到设备消耗明细下钻页
router.push({ path: '/dashboard/asset/ZB-001', query: { yearMonth: '2026-02' } })

// 联动4：从工程人员工作量跳转到记录列表
router.push({ path: '/record', query: { yearMonth: '2026-02', userId: 'U-001' } })

// 联动6：从报警设备分布跳转到设备报警明细下钻页
router.push({ path: '/dashboard/asset-alerts/ZB-001', query: { yearMonth: '2026-02' } })
```

### 7.3 新增页面清单（下钻页）

| 页面 | 小程序路径 | PC 路径 | 云函数 action |
|------|-----------|---------|--------------|
| 配件消耗明细 | `/pages/dashboard/part-detail` | `/dashboard/part/:partSkuId` | `adminDashboard(action: 'partDetail')` |
| 设备消耗明细 | `/pages/dashboard/asset-detail` | `/dashboard/asset/:assetId` | `adminDashboard(action: 'assetDetail')` |
| 设备报警明细 | `/pages/dashboard/asset-alerts` | `/dashboard/asset-alerts/:assetId` | `adminDashboard(action: 'assetAlerts')` |

> 三个下钻页的**更换记录明细展示组件可复用**，字段完全一致：日期 | 数量 | 类型 | 部位 | 填报人 | 备注。设备报警明细页额外包含 ACK 操作按钮（复用已有的 `ackAlert` 云函数）。

### 7.4 目标页面接收参数

目标页面需要在 `onLoad`（小程序）或 `onMounted`（PC Vue）时读取 URL 参数，并用其作为筛选条件的默认值，实现"从看板带参跳转 → 目标页自动筛选"的效果。

### 7.5 小程序 app.json 需新增页面注册

```json
{
  "pages": [
    "pages/dashboard/part-detail",
    "pages/dashboard/asset-detail",
    "pages/dashboard/asset-alerts"
  ]
}
```
