## 一、功能概述

在「业务地图 / 片区态势图」中，通过高德地图检索商户（POI），与内部客户做智能匹配并绑定，提升绑定准确率，并落实**严格 1:1 绑定**（一个内部客户只绑一个外部 POI，反之亦然）。能力覆盖：小程序端 + PC 后台。

核心要点：
- 匹配维度：名称相似度 0.6 + 坐标距离 0.25 + 地址相似度 0.15；**缺失维度按比例重分配权重**（不再一律 0 分）。
- 去掉了电话维度。
- 名称归一化（剥离「大酒店/酒店/连锁/分店」等后缀与符号）+ Levenshtein(O(N) 空间) + Bigram。
- 匹配分档：强烈建议(≥0.8) / 建议(≥0.55) / 无。
- POI 优先建档：直接用高德 POI 建档（精确坐标 + amapPoiId + 自动 1:1 绑定）。
- PC 后台通过 `pcGateway` 用「内部信任令牌 INTERNAL_CALL_TOKEN」转发到 `business-geocode`，复用同一套匹配引擎。

## 五、部署步骤（改完之后）

1. **云函数**：部署 `business-geocode`；重新部署 `pcGateway`（两者都改了或新增）。
2. **环境变量**：给 `pcGateway`、`business-geocode` 配置相同的 `INTERNAL_CALL_TOKEN`；`business-geocode` 另配 `AMAP_KEY`（高德 Web 服务 Key）。
   - 未配置 `INTERNAL_CALL_TOKEN` 时，两函数会基于同环境推导出相同默认值，也能工作；显式配置更稳妥。
3. **用户授权**：在 `users` 集合把业务人员 `role` 设为 `Business`（可管理）或 `BusinessViewer`（只读）；需登录 PC 的加 `canPcLogin: true` 和 `pcPassword`。`Management`/`Admin` 自动获得业务查看权限。
4. **PC 前端**：`cd pc-admin && npm run build`，将 `dist/` 内容上传到静态网站托管根目录（覆盖同名）。
5. **验证**：业务账号登录 → 出现「业务部 / 客户档案 / 片区匹配复核」，可检索高德 POI、批量复核、绑定/解绑。
